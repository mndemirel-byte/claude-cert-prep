## The Core Idea

A multi-agent research system collects data from 5 different sources and writes a synthesis report. The report is beautifully written but one claim is questioned: "Solar energy capacity grew 45%." Which source does this claim come from? When was it published? What is the source's original wording?

If that information was lost during synthesis → **the citation is dead**. The reader can't assess the claim's reliability.

This task statement teaches how to preserve information-source mappings, how to handle conflicting sources, and temporal awareness.

---

## Structured Claim-Source Mappings

### Concept

Five pieces of information must be preserved for every finding:

| Component | Description | Example |
|---|---|---|
| **Claim** | The statement of the finding | "Solar energy capacity grew 45%" |
| **Source URL** | Link to the original source | "https://iea.org/reports/solar-2024" |
| **Document name** | The source's title | "IEA Solar Market Report 2024" |
| **Relevant excerpt** | The relevant passage from the source | "Global solar PV capacity additions grew by 45%..." |
| **Publication date** | The source's publication date | "2024-06-15" |

### Structured Format

```json
{
  "finding": {
    "claim": "Solar energy capacity grew 45% in 2024",
    "source_url": "https://iea.org/reports/solar-2024",
    "document_name": "IEA Solar Market Report 2024",
    "relevant_excerpt": "Global solar PV capacity additions grew by 45% year-on-year...",
    "publication_date": "2024-06-15"
  }
}
```

### Preservation During Synthesis

The critical rule: downstream agents **preserve and merge** these mappings. Even when claims are rephrased during synthesis, the source link must be preserved.

**WRONG — citation loss during synthesis:**
> "Significant growth has occurred in the renewable energy sector. Solar and wind investments have increased."

**RIGHT — citation preserved during synthesis:**
> "Solar energy capacity grew 45% [IEA, 2024-06]. Wind energy investments reached $120B [IRENA, 2024-03]."

## Conflict Handling

### Problem

Two reliable sources report different statistics:

- IEA: "Solar energy capacity grew 45%"
- BloombergNEF: "Solar energy capacity grew 38%"

### Wrong Approach

Don't pick one arbitrarily:

- ❌ "Pick the more recent one"
- ❌ "Pick the better-known source"
- ❌ "Take the average of the two"

### Right Approach

Present both values with their source citations — leave the decision to the consumer:

```json
{
  "claim": "Solar energy capacity growth in 2024",
  "conflicting_values": [
    {
      "value": "45%",
      "source": "IEA Solar Market Report 2024",
      "publication_date": "2024-06-15",
      "methodology_note": "Includes utility-scale and rooftop installations"
    },
    {
      "value": "38%",
      "source": "BloombergNEF New Energy Outlook",
      "publication_date": "2024-03-20",
      "methodology_note": "Utility-scale installations only"
    }
  ],
  "resolution_note": "Difference likely due to scope: IEA includes rooftop, BNEF does not"
}
```

**Rule:** with conflicting sources, don't pick one arbitrarily. Present both values with source citations, state the likely reason for the difference, leave the decision to the consumer.

## Temporal Awareness

### Problem

Two sources report different numbers but it's not a conflict — data from different times:

- Source A (January 2024): "Unemployment rate 5.2%"
- Source B (June 2024): "Unemployment rate 4.8%"

This isn't a conflict but change over time. But without the dates it looks like a conflict.

### Fix

Make publication/data-collection dates mandatory in structured outputs:

```json
{
  "data_points": [
    {
      "metric": "Unemployment rate",
      "value": "5.2%",
      "data_collection_date": "2024-01-15",
      "publication_date": "2024-02-01",
      "source": "National Statistics Office"
    },
    {
      "metric": "Unemployment rate",
      "value": "4.8%",
      "data_collection_date": "2024-06-15",
      "publication_date": "2024-07-01",
      "source": "National Statistics Office"
    }
  ],
  "temporal_note": "Values reflect different time periods, not conflicting data"
}
```

**Rule:** different dates explain different numbers — not a conflict, but change over time. Without dates this distinction can't be made.

## Content-Appropriate Rendering

### Problem

Presenting all findings in a single flat format (e.g. always a list, always a table, always paragraphs) leads to information loss and reduced readability.

### Fix

Each content type should be presented in its natural format:

| Content type | Suitable format | Why |
|---|---|---|
| Financial data | Table | Numeric comparison, relationships between columns |
| News/developments | Prose | Timeline, context, cause and effect |
| Technical findings | Structured list | Quick scanning, categorisation |
| Statistical comparison | Table + chart description | Data density, ease of comparison |

**Rule:** don't squeeze everything into one flat format. Financial data in a table, news in prose, technical findings in a structured list.

## Key Exam Takeaways

| Concept | Remember |
|---|---|
| Claim-source mapping | Every claim: claim + URL + document name + excerpt + date |
| Preservation during synthesis | Downstream agents preserve and merge the mappings |
| Citation death | Without mappings, citations are lost during synthesis |
| Conflict handling | Don't pick one arbitrarily — present both with source citations |
| Temporal awareness | Different dates explain different numbers — not a conflict |
| Mandatory dates | Make publication/data-collection dates mandatory in structured output |
| Content format | Financial → table, news → prose, technical → structured list |

## Practice Scenario 1

> A multi-agent research system is writing an energy-sector report. The synthesis agent produces this sentence:
>
> "Notable growth has been observed in the renewable energy sector in recent years. Solar energy capacity has increased significantly."
>
> The reader asks: "By what percentage? Which source? Which year?"
>
> The web search subagent had actually found specific data: 45% according to the IEA report, 42% according to the IRENA report.
>
> **What are the root cause and the fix?**
>
> **A)** Add "be specific" to the synthesis agent's system prompt.
>
> **B)** Structured claim-source mappings are missing from the data passed from the web search subagent to the synthesis agent. Change the handoff format to include structured claim-source mappings.
>
> **C)** The synthesis agent's context window is small — use a bigger model.
>
> **D)** Have the web search subagent search in more detail.

### Correct Answer: B

**Why B is correct:** citation death — the web search subagent found specific data but it wasn't passed to the synthesis agent in a structured format. Without knowing the sources and values the synthesis agent uses vague phrases. Fix: pass every claim mapped to source, URL, date and value via structured claim-source mappings.

**Why A is wrong:** a prompt instruction doesn't fix a structural problem. If the data reaching the synthesis agent has no source mapping, saying "be specific" can't create the missing data.

**Why C is wrong:** the problem isn't the context window size but the data format. A bigger model can't produce source citations from unstructured input either.

**Why D is wrong:** the web search agent already found specific data — search quality isn't the problem. The problem is the handoff format.

## Practice Scenario 2

> A research report contains these two findings:
>
> - Source A (IEA, January 2024): "Global carbon emissions 37.4 Gt"
> - Source B (IEA, July 2024): "Global carbon emissions 36.8 Gt"
>
> The agent flags this as "conflicting data" and can't decide which value is correct.
>
> **What is the right approach?**
>
> **A)** Use the more recent value (36.8 Gt) — the latest data is always correct.
>
> **B)** Take the average of the two — 37.1 Gt.
>
> **C)** Present both values with source citations and dates. Note that the difference may be temporal — different measurement periods give different results.
>
> **D)** Remove both sources — conflicting data is unreliable.

### Correct Answer: C

**Why C is correct:** temporal awareness + conflict handling. Two values from the same source on different dates — not a conflict but different measurement periods. Present both values with dates and state the temporal context.

**Why A is wrong:** the assumption "the latest data is correct" doesn't always hold. The January data may belong to 2023, the July data to the first half of 2024 — they measure different periods.

**Why B is wrong:** averaging statistics is meaningless — it mixes the measurements of two different periods. The result represents neither period.

**Why D is wrong:** removing data that looks conflicting is information loss. Differences explainable by temporal context aren't unreliable.
