## The Core Idea

How do you break large tasks into pieces? There are two fundamental patterns, and you need to know when each one is the right call.

---

## Pattern 1: Fixed Sequential Pipelines (Prompt Chaining)

You split the work into predetermined, ordered steps. Each step's output becomes the next step's input.

Example — code review:

1. Analyze each file individually
2. Then run an integration pass that checks dependencies across all files

**When to use it:** Predictable, structured tasks — code review, document processing, data transformation.

**Advantage:** Consistent and reliable.

**Limitation:** Can't adapt to unexpected findings.

---

## Pattern 2: Dynamic Adaptive Decomposition

You generate subtasks dynamically, based on what's discovered at each step.

Example — "add tests to a legacy codebase":

- First, map the structure
- Identify high-impact areas
- Build a prioritized plan as dependencies emerge

**When to use it:** Open-ended research tasks, problems that require exploration.

**Advantage:** Adapts to the problem.

**Limitation:** Less predictable.

---

## The Attention Dilution Problem (Exam Trap)

This one matters a lot. If you process too many files or too much data in a single pass, Claude's attention gets diluted. The result: it gives detailed feedback on some files while missing obvious errors in others. Worse — **it can flag the same pattern as a problem in one file while approving the identical code in another**. This inconsistency is the telltale sign of attention dilution.

**The fix: multi-pass architecture.**

- **Pass 1 — Per-file local analysis:** Review each file individually. Catch local issues.
- **Pass 2 — Cross-file integration:** Check data flow, dependencies, and inconsistencies across files.

The per-file pass consistently catches local issues; the integration pass catches cross-file issues.

---

## Key Exam Takeaways

| Concept | Remember |
|---|---|
| Fixed sequential pipelines | Predetermined, ordered steps — for predictable tasks |
| Dynamic adaptive decomposition | Dynamic subtasks based on discovered information — for open-ended research |
| Attention dilution | Too much data in one pass → inconsistent depth and contradictory judgments |
| Multi-pass architecture | Per-file local analysis + cross-file integration — the fix for attention dilution |
| Exam trap | Solutions like "add an instruction to pay equal attention to everything" don't fix the structural problem — reject them |

## Practice Scenario

> A code review agent analyzes a 14-file pull request in a single pass. The results:
>
> - It gives very detailed feedback on some files while missing obvious bugs in others
> - It flags a pattern as an "anti-pattern" in file 3, but approves the same code in file 11
>
> **What's the problem, and how do you fix it?**
>
> **A)** The agent's context window is too small — use a bigger model.
>
> **B)** Processing 14 files in a single pass is causing attention dilution — switch to a multi-pass architecture: per-file local analysis plus cross-file integration.
>
> **C)** Add an instruction to the agent's system prompt: "pay equal attention to every file."
>
> **D)** Sort the files by priority instead of alphabetically.

### Correct Answer: B

**Why B is correct:** Processing 14 files in a single pass dilutes Claude's attention. Inconsistent depth and contradictory reactions to the same pattern are the classic symptoms. A multi-pass architecture — analyze each file individually first, then run a cross-file integration pass — fixes both problems.

**Why A is wrong:** The problem isn't context window size, it's attention dilution. A bigger model would face the same issue, because trying to focus on 14 files in one pass is a structural problem.

**Why C is wrong:** A prompt instruction is probabilistic. Saying "pay equal attention" doesn't fix attention dilution — this is a structural architecture problem, not a prompt problem.

**Why D is wrong:** Reordering the files changes which ones get neglected but doesn't fix the underlying issue. It's still a single pass, still diluted attention.
