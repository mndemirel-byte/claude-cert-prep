## The Core Idea

When you give Claude Code a task there are two basic modes: **plan mode** (think first, then act) and **direct execution** (act immediately). The exam expects you to know which to use when.

---

## Plan Mode — Think First, Then Act

In plan mode Claude Code first **analyses, explores, designs** — then implements once approved.

### When to Use It?

- **Complex tasks** — large-scale changes
- **Several valid approaches** exist — you need to evaluate which is best
- **Architectural decisions** are needed
- **Multi-file changes** — e.g. a library migration touching 45+ files
- **Exploration is required** — inspecting and designing the codebase before changing it

### Examples

| Task | Plan mode? | Why? |
|---|---|---|
| Convert a monolith to microservices | ✅ Yes | Architectural decision, many approaches |
| Replace the logging library in 30 files | ✅ Yes | Multi-file, impact analysis needed first |
| Understand and restructure a legacy codebase | ✅ Yes | Exploration needed, design needed |

---

## Direct Execution — Act Immediately

In direct execution Claude Code goes **straight to implementation** without planning.

### When to Use It?

- **Well-understood changes** — clear and bounded scope
- **Single-file bug fix** — with a clear stack trace
- **Simple addition** — such as adding a date-validation condition
- **The right approach is already known** — no exploration or comparison needed

### Examples

| Task | Direct? | Why? |
|---|---|---|
| Fix a null pointer in a single function | ✅ Yes | Clear bug, single file, clear fix |
| Add validation to a date field | ✅ Yes | Bounded scope, clear requirement |
| Add setup steps to the README | ✅ Yes | Simple addition |

---

## The Explore Sub-Agent

In multi-stage tasks the **Explore sub-agent** comes into play:

- **Isolates detailed exploration output** from the main conversation
- Returns **summaries** to the main conversation
- **Prevents context window exhaustion**

Think of the Explore sub-agent as someone who goes and does the research for you, then summarises only the important findings — not all the raw data.

### When to Use It?

- When you need to explore and understand the codebase
- When many files will be inspected
- When you want to protect the main conversation's context

---

## The Combination Pattern (Hybrid Approach)

The most tested approach in practice and on the exam:

1. Research and design with **plan mode**
2. Implement the planned approach with **direct execution**

Combining the two is a common and expected pattern.

### Example Flow

```
Task: migrate 30 files from log4j to SLF4J

Step 1 (plan mode):
- Discover the affected files
- Analyse import patterns
- Identify configuration differences
- Create a migration plan

Step 2 (direct execution):
- Update the files per the plan
- Replace the imports
- Update configuration files
```

## Decision Table

| Task characteristics | Mode | Rationale |
|---|---|---|
| Complex, several approaches | **Plan mode** | Evaluation needed |
| Multi-file change | **Plan mode** | Impact analysis first |
| Architectural decision | **Plan mode** | Design needed |
| Exploration required | **Plan mode** | Understand first, then act |
| Single file, clear bug | **Direct** | Clear fix, do it now |
| Simple addition, bounded scope | **Direct** | Planning unnecessary |
| Approach already known | **Direct** | Evaluation unnecessary |
| Research + implementation | **Hybrid** | Plan → direct execution |

## Key Exam Takeaways

| Concept | Remember |
|---|---|
| Plan mode | Complex tasks, many approaches, architectural decisions, exploration needed |
| Direct execution | Clear bug, bounded scope, approach known |
| Explore sub-agent | Isolates detailed exploration, returns summaries, preserves context |
| Hybrid approach | Plan mode → direct execution: research, design, then implement |
| Exam hint | "45 files", "migration", "restructuring" → plan mode |
| Exam hint | "single file", "null pointer", "simple fix" → direct execution |

## Practice Scenario 1

> There are three tasks. Classify each as plan mode or direct execution:
>
> 1. Converting a monolithic application to microservices
> 2. Fixing a null pointer error in a single function (stack trace available)
> 3. Migrating from one logging library to another across 30 files
>
> **A)** 1: Plan, 2: Plan, 3: Direct
>
> **B)** 1: Plan, 2: Direct, 3: Plan
>
> **C)** 1: Direct, 2: Direct, 3: Plan
>
> **D)** 1: Plan, 2: Direct, 3: Direct

### Correct Answer: B

**Why B is correct:**
1. **Monolith → microservices = plan mode.** Architectural decision, several approaches, large-scale change. Analyse first, design, then implement.
2. **Null pointer fix = direct execution.** Single file, stack trace available, clear bug, clear fix. Planning unnecessary.
3. **Library migration across 30 files = plan mode.** Multi-file change; discover the affected files first, analyse import patterns, then implement.

**Why A is wrong:** plan mode is unnecessary for task 2 (null pointer) — a clear bug in a single file, fix it directly.

**Why C is wrong:** direct execution is dangerous for task 1 (monolith conversion) — implementing an architectural decision without exploration and design creates chaos.

**Why D is wrong:** direct execution is risky for task 3 (30-file migration) — impact analysis and a plan are needed first.

## Practice Scenario 2

> A developer works in a large codebase. They want to understand and restructure a legacy module. The module consists of 25 files with unclear dependencies.
>
> The developer wants to follow this approach:
> - First explore the codebase and map the dependencies
> - Then create a restructuring plan
> - Finally implement the plan
>
> But they worry that the exploration phase will produce too much detailed output — polluting the main conversation's context.
>
> **What is the right approach?**
>
> **A)** Do the whole process with direct execution — exploration is unnecessary.
>
> **B)** Use the Explore sub-agent in the exploration phase (isolates detailed output, returns a summary), then design in plan mode, finally implement with direct execution.
>
> **C)** Read the 25 files one by one with Read and load them all into the main conversation.
>
> **D)** Do everything at once in plan mode — exploration, design and implementation together.

### Correct Answer: B

**Why B is correct:** a three-stage hybrid approach:
1. Exploration with the **Explore sub-agent** — detailed output stays in the isolated context, only summaries return to the main conversation. The context window is preserved.
2. Design with **plan mode** — create the restructuring plan based on the exploration findings.
3. Implementation with **direct execution** — implement the plan.

**Why A is wrong:** a 25-file legacy module with unclear dependencies — exploration is absolutely necessary. Starting with direct execution means changing things blindly.

**Why C is wrong:** loading 25 files sequentially into the main conversation exhausts the context window. The Explore sub-agent solves exactly this — isolates and summarises.

**Why D is wrong:** the exploration phase produces very detailed output — combining it with plan mode pollutes the main conversation's context. The Explore sub-agent exists to isolate exploration.
