## The Core Idea

Task Statement 1.4 covered why programmatic enforcement is necessary. Now we learn **how** it's implemented. The answer: **hooks**.

Hooks are pieces of code you place **before** or **after** a tool call. There are two main types:

---

## PostToolUse Hooks (After the Tool Runs)

Intervenes **after** the tool runs, **before** the result reaches Claude.

**Purpose: data normalization.**

Different MCP tools return data in different formats — one returns a Unix timestamp, another ISO 8601. One returns a numeric status code, another a string. A PostToolUse hook converts all of these varied formats into a standard one.

Result: Claude always sees clean, consistent data — regardless of which tool produced it.

---

## Tool Call Interception Hooks (Before the Tool Runs)

Intervenes **before** the tool is called.

**Purpose: enforcing business rules.**

Examples:

- Block refunds over $500 and route them to a human escalation workflow
- Prevent international transfers from being processed without a compliance check
- Require manager approval for specific operations

---

## Decision Framework

| Approach | Guarantee | Use for |
|---|---|---|
| **Hooks** | Deterministic — runs 100% of the time | Business rules, compliance, financial controls |
| **Prompts** | Probabilistic — works most of the time | Preferences, style rules, soft guidance |

> **If a single failure would cost money or create legal risk → use a hook.**

---

## Key Exam Takeaways

| Concept | Remember |
|---|---|
| PostToolUse hooks | Intercepts tool results before Claude sees them — for data normalization |
| Tool call interception | Intercepts before the tool runs — for enforcing business rules |
| Hook = deterministic | 100% guarantee — business rules, compliance, financial controls |
| Prompt = probabilistic | Works most of the time — sufficient for preferences and soft rules |

## Practice Scenario

> An agent occasionally processes international transfers without the required compliance checks. This creates regulatory risk.
>
> **Solution: a hook, or improved prompt instructions? Why?**

### Correct Answer: Hook

**Explanation:** Regulatory risk means a single failure creates legal consequences. Prompt instructions can raise the success rate (say, from 92% to 97%) but can't guarantee 100%. A tool call interception hook physically blocks the transfer tool from running until the compliance check completes. Zero failure rate.

**Why a prompt isn't enough:** International transfers are subject to financial regulation. Even a single uncontrolled transfer carries the risk of penalties or legal investigation. A probabilistic solution is unacceptable at this risk level. A deterministic guarantee is required.
