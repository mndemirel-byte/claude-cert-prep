## The Core Idea

Claude Code has built-in tools — basic operations such as reading, writing and searching files. The exam expects you to know when to use each, and in particular **the difference between Grep and Glob**.

---

## Grep vs Glob — The Critical Distinction

Mixing these two up costs you time on the exam or leads to the wrong answer.

### Grep — Searching File CONTENTS
Searches for patterns in the **text inside** files.

**Use cases:**
- Finding the places that call a function
- Searching for error messages
- Finding import statements
- Finding files that use a specific variable name

**Example:** find all files that call the function `deprecatedFunction` → **Grep**

### Glob — Matching File PATHS
Matches file **names and paths** against a pattern.

**Use cases:**
- Finding files by extension (`**/*.test.tsx`)
- Finding configuration files (`**/config.*`)
- Listing files in a particular directory structure

**Example:** find all test files → **Glob** (`**/*.test.tsx`)

### Summary Table

| Tool | Searches for | Where | Example |
|---|---|---|---|
| **Grep** | Text pattern | File **contents** | Function calls, error messages, imports |
| **Glob** | Name pattern | File **paths** | Finding files by extension, config files |

## Read / Write / Edit

### Edit — Targeted Change
Makes a **targeted** change using unique text matching. Fast and precise.

**When to use:** when the text you want to change is unique in the file.

### When Edit Fails — The Read + Write Fallback

Edit sometimes fails — if the text you want to match is **not unique** in the file (appears in more than one place). Then the fallback is:

1. **Read** — load the entire file
2. **Write** — write the entire modified file

**Read + Write** is the reliable fallback when Edit cannot find a unique anchor text.

### Summary

| Tool | Use | Advantage | Limitation |
|---|---|---|---|
| **Edit** | Targeted change via unique text match | Fast, precise | Text must be unique |
| **Read + Write** | Load full file + write full file | Always works | Slower, processes the whole file |

---

## Incremental Codebase Understanding

The right approach to understanding a large codebase:

1. **Find entry points with Grep** — function definitions, import statements
2. **Follow imports with Read** — trace flows from the entry points
3. **Do not read all files upfront** — this is a context-budget killer

> **Reading all files upfront is the WRONG approach.** It fills the context window with unnecessary data. Instead: identify targets with Grep, read only the necessary files with Read.

### Tracing Function Usage

To trace function usage across wrapper modules:
1. First identify the exported names
2. Then Grep for each name across the codebase

## Key Exam Takeaways

| Concept | Remember |
|---|---|
| Grep | Search file CONTENTS — function calls, error messages, imports |
| Glob | Match file PATHS — files by extension, config files |
| Edit | Targeted change via unique text match — fast and precise |
| Read + Write | Fallback when Edit fails — load and write the full file |
| Incremental understanding | Grep → Read → follow. Never read all files upfront — context-budget killer |
| Exam trap | Confusing Grep and Glob — content search or path match? |

## Practice Scenario

> A developer wants to find all files that call a deprecated function (`oldCalculate`) in the codebase, and for each of those files also find the corresponding test files.
>
> **What is the correct tool sequence?**
>
> **A)** Find all `.ts` files with Glob, then Read each one and filter those containing `oldCalculate`.
>
> **B)** Grep for the function name `oldCalculate` (finds the callers), then match the test files corresponding to the found file names with Glob (`**/*.test.tsx`).
>
> **C)** Read all files one by one and manually search for the string `oldCalculate`.
>
> **D)** Use Glob with the pattern `**/*oldCalculate*` to find files containing the function.

### Correct Answer: B

**Why B is correct:** The correct two-step sequence:
1. **Grep** for the function name `oldCalculate` in file contents → finds the files that call this function
2. **Glob** to match the test files corresponding to the found file names (`**/*.test.tsx`)

Each tool is used where it is strong: Grep for content search, Glob for path matching.

**Why A is wrong:** Finding all `.ts` files and reading them all is inefficient — a waste of context budget. Grep finds the target directly.

**Why C is wrong:** Reading all files sequentially is the worst approach — very slow, a context-budget killer. Grep does this job in one step.

**Why D is wrong:** Glob searches file **paths**, not file **contents**. If the function name `oldCalculate` does not appear in a file name (and it usually doesn't), Glob returns nothing. Content search needs Grep.
